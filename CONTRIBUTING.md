# Contribuer à HashCode Foundations

Merci de contribuer à la qualité des ressources pédagogiques de HashCode.

## Avant de contribuer

- Vérifier qu'un sujet similaire n'existe pas déjà.
- Consulter le README du parcours concerné.
- Ouvrir une issue pour discuter d'un changement important de structure ou de périmètre.

## Principes de contenu

1. Écrire en français clair et adapté à un public débutant.
2. Définir les acronymes et les termes techniques à leur première apparition.
3. Distinguer les faits, les exemples et les recommandations.
4. Ajouter des sources fiables pour les affirmations techniques et les points susceptibles d'évoluer.
5. Tester les commandes dans un environnement adapté et préciser le système concerné.
6. Ne jamais intégrer de secrets, de données personnelles, de véritables identifiants ou d'informations sensibles.
7. Les exercices de sécurité doivent se limiter à des environnements autorisés et isolés.

## Modèle recommandé pour un chapitre

- Objectifs d'apprentissage observables
- Prérequis
- Vocabulaire essentiel
- Explications structurées
- Exemple ou démonstration
- Exercices avec résultats attendus
- Quiz de vérification
- Résumé
- Références

## Qualité avant fusion

- Le Markdown est lisible et les liens fonctionnent.
- Les commandes ont été vérifiées ou sont clairement présentées comme illustratives.
- Les exercices ont des consignes, un contexte et un résultat attendu.
- Les références sont pertinentes et accessibles.
- Le contenu ne suppose pas de connaissances non expliquées.

## Pull requests

Décrire le problème pédagogique, le changement proposé, les chapitres concernés et les vérifications réalisées. Privilégier une pull request ciblée plutôt qu'un changement massif difficile à relire.
